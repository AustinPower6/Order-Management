User documentation — all features, internal relationships and workflows explained.

Start & Navigation

The application opens with a start page and a sidebar on the left. Use the sidebar to quickly reach all functions.

Clicking a button in the sidebar or menu opens the corresponding module as a tab on the right. Several tabs can be open at the same time.

  • Close a tab: click the X on the tab
  • Close a tab (alternative): double-click the tab

The main window automatically saves its position and size. On the next start it is restored at the same location.

Sidebar & Document Date

The sidebar on the left shows the current document date below the user name. This date is used as the default value for new documents (quote, order, delivery note, invoice, reminder).

Setting an override date

By default the document date matches today's date. However, you can set an arbitrary override date:

  • Left-click on the date opens a calendar dialog where you can pick any date.
  • Right-click on the date shows a context menu:
    • Set to today's date — resets the document date to today.
    • Remove override date — removes the manually set date; today's date is used again from now on.

The override date is not persistent — on application restart it is automatically reset to today's date. This prevents mistakes from working with yesterday's date the next day.

Practical tip: The override date is useful when you need to create a document retroactively (e.g. an invoice on March 5 for a delivery from February 28).

Master Data — Overview

Master data is the foundation of every document. Without correct master data, neither PDF printouts nor document chains work correctly.

The three master data modules are interconnected:

  • Company — your business: address, bank details, VAT classes, conditions, standard texts, markers
  • Customers — recipients of all documents; every document references a customer
  • Articles — products and services; every line item on a document references an article

Company

The company module is the central configuration. It is split into several tabs:

Address & Contact

Name, additional line, street, ZIP, city, phone, fax, email, website. This data appears as the sender on every PDF printout.

Parameters

Tax number, VAT ID, IBAN, BIC, bank name, currency, country code. This data appears in the footer of every invoice and every reminder. You also configure here:

  • Create e-invoice: Activates automatic generation of machine-readable XML files on the first print of an invoice (EN 16931).
  • Email client: Sets which service is used to send emails (Brevo, Gmail, Outlook 365 Classic, New Outlook). Details see Email Outbox.
  • Email signature & privacy policy: Appended automatically to the email text.

Fiscal Years & Document Numbers

Manage fiscal years and configure counters for all document types here. Details see Document Numbers & Fiscal Years.

Payment Terms

Define the default payment terms offered to customers. Details see Payment Terms.

Reminder Terms

Multi-level reminder configuration: due period, interest rate, reminder fee per level. Details see Reminder Terms.

VAT Classes

Define tax classes here (e.g. “Standard rate”, “Reduced rate”, “Tax-free”) and assign time-dependent rates. Details see VAT System.

Base Interest Rate

Historical base interest rates of the central bank for calculating default interest. Details see Base Interest Rate.

Print Texts

Configurable labels and captions in the PDF documents (e.g. “Invoice no.:”, “Due on:”, “Total amount:”). This way you can adapt documents to your needs.

Signatures

Default signatures for the different document types.

Standard Texts

Text snippets for quotes, orders, invoices, delivery notes and reminders — including the staged reminder texts (Payment reminder, 1st reminder, 2nd reminder, Final notice). You can use markers that are replaced automatically when printing. Details see Standard Texts & Markers.

Copies

Paths

Export paths for PDFs (optional) and other file settings.

Locks

Modules can be locked against unwanted changes. Details see Locking System.

Save and Cancel

Each tab has its own Save and Cancel buttons at the bottom. Changes are only applied when you click “Save”. With “Cancel” you discard all pending changes in that tab. A red dot on a tab indicates unsaved changes.

Workflow & Document Chain

The typical workflow runs in stages. Not every stage is mandatory: you can go directly from quote to order, and from order to invoice (skipping the delivery note), and the reminder process is only triggered on unpaid invoices.

Document flow: mandatory chain and optional paths. Status changes appear on the respective document.

Document Chain in Detail

Every document is linked to its predecessors and successors. This linking is called the document chain. The link is established through foreign keys (IDs) on the successor document that point to the predecessor.

Document chain: each successor stores the ID of its predecessor. Bidirectional navigation starts from any document in the chain.

In detail:

  • Quote → Order: The order stores the angebot_id. The system thus knows from which quote the order originated.
  • Order → Delivery Note: The delivery note stores the auftrag_id.
  • Order → Invoice: The invoice stores the auftrag_id.
  • Delivery Note → Invoice: The invoice optionally stores the lieferschein_id.
  • Invoice → Reminder: Every reminder stores the rechnung_id and the mahnstufe (level).
  • Reminder → next level: Higher-level reminders point to the previous reminder.
Document chain in the dialog: When you open a document, you see the entire chain at the top — from the first quote to the last reminder. Deleted documents are shown with a marker so the chain remains traceable even after deletions.

Backward and forward through the chain

The document chain is bidirectional:

  • Backward: From the current document to the first predecessor (usually the quote). This always shows which quote an invoice is based on.
  • Forward: From the current document to the last successor (e.g. from the invoice to the highest reminder level). This shows how overdue a payment is.

Delete protection through the chain

When you try to delete a document that has live successors, deletion is prevented. The system shows a warning with the list of blocking documents.

Example: You cannot delete a quote if an order has already been created from it. You cannot delete an order if an invoice already exists.

Caution: This only applies to live (not deleted) successors. If the order has already been deleted, you can delete the quote.

Delete & Restore

Documents are never actually deleted, but marked as deleted (soft delete). This has the following effects:

  • Deleted documents do not appear in the normal lists.
  • Deleted documents appear in the document chain with a marker (e.g. struck-through or grey).
  • Deleted documents can be restored — they reappear in the list.
  • The number of a restored invoice is not reassigned (it keeps its original number).

Preventing deletion (delete protection)

The system checks for live successors before every deletion:

Document typeDeletion blocked by
QuoteLive order
OrderLive delivery note or live invoice
Delivery NoteLive invoice referencing this delivery note
InvoiceLive reminders
ReminderLive higher-level reminders

Document Numbers & Fiscal Years

Every document type has its own counter, configured in the company module.

Format

The format is: {Prefix}{YYYY}-{NNNN}

Document typeExample
QuoteAN2026-0001
OrderAU2026-0018
Delivery NoteLS2026-0009
InvoiceRE2026-0008
ReminderMA2026-0003

How the counter works

  • The counter stores the last assigned number (not the next one).
  • The preview shows the number you will get — without incrementing the counter.
  • The counter is only incremented when the document is saved.
  • If you create a document and then do not save it, the number is not consumed.
Practical tip: When you see the preview (e.g. “RE2026-0015”), it means: “If you save now, you will get this number.” As long as you do not save, the counter stays unchanged.

Fiscal years

You can manage multiple fiscal years. Each year has its own document counters and its own booking month.

Switching fiscal year:

  • Select the desired year from the drop-down in the “Fiscal Years & Document Numbers” tab.
  • Right-click on the drop-down sets the selected year as the active fiscal year.
  • Booking month and counters are stored per year and switch with the year.

Creating a new fiscal year:

  • Click the “New fiscal year…” button next to the drop-down.
  • The system suggests the next year (current year + 1).
  • The year number MUST be higher than the last one — this guarantees chronological order.
  • The new year is immediately set as the active year.

The active fiscal year is shown in the sidebar (below the document date, with a calendar icon).

VAT System

The VAT system works with classes and time-dependent rates.

Classes

Every VAT class (e.g. “Standard rate”, “Reduced rate”, “Tax-free”) has multiple rates with a start date. Example:

ClassRateFrom date
Standard rate15 %01.01.2024
Standard rate16 %01.07.2024
Standard rate18 %01.01.2025
Reduced rate7 %01.01.2024

Freezing the VAT rate

When you create a line item on a document, the rate valid at the document date is stored in the line item. The rate is thus frozen — later changes to the VAT class do not affect the document anymore.

When a line item is created, the system reads the rate valid at the document date from the VAT class and stores it permanently in the line item. Later changes to the class do not affect the document.

Example sequence:

  • Document of 2025-03-15 with standard rate → line item gets 18 %
  • Rate increase to 20 % effective 2025-06-01
  • Document of 2025-06-10 with standard rate → line item gets 20 %
  • The old document of 2025-03-15 stays at 18 %
Why this matters: When you reprint old documents, they show the correct VAT rate for the time of creation. Nothing needs to be adjusted manually.

Document dialog — layout

As soon as you create or edit a document, the document dialog opens. It is structured in four blocks:

The document dialog: identical structure for all document types, document-type-specific fields appear in the header data.

Step by step editing a document

  1. Open document: select the document in the list and click Edit or double-click the row.
  2. Check/adjust header data:
    • Change Date (clicking the date field opens a calendar)
    • Pick a Customer via the button (search by name, company, customer number)
    • Choose Payment terms from the drop-down — the due date is calculated automatically
    • Enter Subject (spell-check active)
    • Adjust Top text if needed; insert markers (e.g. {RENR}) via button click
  3. Edit line items: see Line-Item Editor below.
  4. Adjust Bottom text (analogous to top text).
  5. Check the chain via the Document chain button — shows all predecessors and successors.
  6. Save or Cancel. With unsaved changes a confirmation appears before closing (“Save / Discard / Cancel”).
Keys in the document dialog: F1 opens the documentation (chapter “Editing Documents”). Esc closes the dialog, but asks first if there are unsaved changes.

What works, what doesn't

  • New document number: assigned from the counter on save. The preview in the dialog only shows what you would get. As long as you do not save, the document consumes no number.
  • Existing document number: cannot be changed. It stays fixed throughout the document's lifetime.
  • Paid invoices: are locked and can no longer be edited (a notice is shown).
  • Documents with successors: are partly locked — a quote that became an order is in status “accepted” and can no longer be edited.
  • Multiple tabs at once: A list and a document dialog can be open in parallel. Save the dialog so the list sees the new values (or F5 in the list).

Quotes

Create a quote

  1. Button + or Ctrl+N
  2. Select a customer from the drop-down (search by name/company)
  3. Set the date (default: today or override date)
  4. Optional: specify the validity of the quote
  5. Add line items: select article, enter quantity, adjust price if needed
  6. Enter subject and optional free text
  7. Save

Convert quote to order

Select the quote from the list and click → Order:

  • The quote status is set to “accepted”
  • All line items are copied
  • The order is created with the same customer
  • The document chain connects the quote and the order

You can then edit the order (change line items, adjust date).

Print a quote

Select the quote and click Print. A PDF is generated and opened in the viewer.

Orders

Create an order

Orders can be created in two ways:

  1. From a quote: button → Order in the quote list
  2. Manually: button + in the order list

Convert order to delivery note

Button → Delivery Note — copies customer, date and line items.

Convert order directly to invoice

Button → Invoice — skips the delivery note. The order status is set to “completed”.

Workflow note: From an order you can create both a delivery note and an invoice. If you do both, the invoice references both the order and the delivery note.

Delivery Notes

Delivery notes are created from orders. They document the delivery.

  • On delivery notes no prices are shown
  • Quantities and articles are copied from the order
  • You can adjust quantities on the delivery note (e.g. for partial deliveries)

Convert delivery note to invoice

Button → Invoice — copies all data and sets the delivery date.

Invoices

Create an invoice

Invoices are created via the → Invoice button in the delivery notes list. The delivery note must have been created from an order first.

If no delivery note is needed, you can create a delivery note from the order and immediately convert it to an invoice. There is no direct “Order → Invoice” button.

Payment terms

The invoice inherits the payment terms from the customer (if configured). The due date is calculated automatically: Invoice date + terms in days.

Creation date

The creation date is locked on the first print of a document (date + time). After that it stays unchangeable. It appears:

  • In the document dialog, top right of the header block
  • In the PDF header, top right of the company header

For a test print no creation date is stored (display: “99.99.9999”).

Mark as paid

Select the invoice and click Mark as paid:

  • The paid date is set to today
  • Paid invoices can no longer be edited afterwards
  • Paid invoices are shown in the list with an appropriate marker
Caution: An invoice marked as paid can no longer be changed. Make sure all data is correct before doing so.

Finalise an invoice

On the first real print (not a test print) an invoice is automatically finalised:

  • The creation date and time are locked and cannot be changed.
  • Finalised invoices can no longer be edited — only cancelled.
  • A red “FINALISED” notice appears in the document dialog.

Cancel an invoice

A finalised invoice can be cancelled via the “Cancel” button:

  1. The original invoice receives the status “cancelled” and can no longer be edited.
  2. A new cancellation invoice with the same line items but negative amounts is created automatically.
  3. The cancellation invoice is shown in the list with the prefix “Storno:” and can also be printed.
  4. Optionally a corrected invoice can be created directly from the cancellation.
Caution: Cancellation is irreversible. Make sure you have selected the correct invoice.

Invoice to reminder

Button → Reminder — creates the next reminder based on the reminder terms (from the customer or company). The reminder level is determined automatically.

Reminders

How reminders work

The reminder process is staged. Levels are assigned automatically (1 to 4):

LevelDescription
1Payment reminder
21st reminder
32nd reminder
4Final notice

Each level has:

  • A due period in days (e.g. 7, 14, 30 days)
  • Optional: reminder fee in euros
  • Optional: interest rate in percent

Create a reminder

  1. Use the button → Reminder in the invoice list
  2. The reminder is created with the next free level
  3. Print → PDF is generated

Default interest

If an interest rate is defined for the reminder level, a default interest charge is calculated:

  • Calculation: open amount × interest rate / 100 × days / 365 (day-precise per period)
  • The charge is shown as a tax-free line item
  • It appears below the total amount
  • At interest rate 0 % (level 1 — payment reminder), no interest is calculated

Next reminder level

Button → Next Level — creates the next reminder of the terms:

  • The reminder level increases by 1 (e.g. from 1st to 2nd reminder)
  • The reminder terms of the next level are applied
  • If the maximum (4) is already reached, a warning appears
Document chain on reminders: When you open a reminder, you see the entire chain: Quote → Order → Delivery Note → Invoice → Payment reminder → 1st reminder → 2nd reminder etc.

Conditions

Payment Terms

Payment terms determine how long a customer has to pay after an invoice has been issued.

How it works

  • You define terms in the company module (e.g. “14 days net”, “30 days net”, “immediate”)
  • Every term has a number of days and a description
  • A customer can be assigned a default term
  • When an invoice is created, the due date is calculated: Invoice date + terms in days

Examples

Reminder Terms

Reminder terms determine the behavior of the reminder process per level.

How it works

  • You define reminder levels in the company module
  • Each level has: description, due days, reminder fee, interest rate
  • A customer can have their own reminder terms (overrides the default terms)
  • If no customer-specific terms are defined, the default terms are used

Base Interest Rate

The base interest rate of the central bank serves as the basis for calculating default interest.

  • You can maintain historical base interest rates with a start date
  • The system determines the rate valid at the time of the reminder
  • The base interest rate is used to set the default interest rate
  • If the interest rate in the reminder terms is 0 %, no base interest rate is added

Standard Texts & Markers

In the company module you can define standard texts for every document type. These texts are displayed on the documents (PDFs).

How it works

  • You write a text snippet in the Standard Texts tab
  • The text is used when printing the respective document type
  • You can include markers that are replaced automatically
  • Each document type is embedded in a collapsible box
  • For reminders there are separate texts per level: payment reminder, 1st reminder, 2nd reminder, final notice

Marker buttons in document dialogs

In document dialogs (e.g. when creating a quote or invoice) you find clickable marker buttons below the “Top text” and “Bottom text” fields. A click inserts the corresponding marker at the cursor position.

The available markers are cumulative: an order shows AN and AU markers, a delivery note shows AN, AU and LS markers, an invoice shows everything up to RE, a reminder shows all markers.

Marker System

Markers are placeholders replaced automatically by the corresponding values at print time. The format is: {PrefixSuffix} (e.g. {ANNR}, {REFÄLLIG}).

Marker pipeline: standard text → parser → values from the document chain → substituted text on the PDF. Markers without a value in the chain are silently removed together with the surrounding sentence.

General marker reference

Marker names use the original German prefixes/suffixes so a single set of markers works in both languages (e.g. {REFÄLLIG} = invoice due date, {ANNR} = quote number, {REGESAMT} = invoice gross total).

Printing & Journals

Printing Individual Documents

Select a document in the list and click Print (or Ctrl+P).

  • The PDF is automatically saved in the directory Ausdrucke/{YYYY}/{MM}/{DD}
  • If no export path is configured in the company module, the PDF is saved in the application directory
  • File name: {Type}_{DocumentNumber}.pdf
  • The PDF opens automatically in the default PDF viewer
  • The header of the PDF contains your company data
  • The footer contains bank details and configurable print texts

PDF content

Every PDF contains:

  • Company logo (if configured)
  • Sender address (from company module)
  • Recipient address (from customer module, stored at the time of the document)
  • Document number and date
  • Subject line
  • Line-item table with article number, description, quantity, unit, unit price, VAT, total
  • Subtotal, VAT entries per rate, total amount
  • Payment conditions (due date, bank details)
  • Optional: standard text from company settings
  • Document chain (predecessor numbers)
  • Creation date (top right in the header)

Next page hint

If a document spans multiple pages, the hint “Please see next page N!” appears on every page up to the penultimate one, directly below the total price. On the last page this hint is not shown.

Test Print

The test print produces a PDF that looks identical to the real print, but with a TEST PRINT watermark on every page. The watermark is guaranteed to be on top of the document content.

  • The test print does not store a creation date in the database
  • In the test print PDF, “99.99.9999” appears top right as a placeholder
  • The file name starts with TEST_

Printing Journals

Under Reports → Print Journal you can produce document lists as PDF:

  • Choose document type: quotes, orders, delivery notes, invoices, reminders (or all)
  • Choose year and month
  • The journal shows all documents of the chosen period with number, date, customer and amount
  • Print PDF — export the entire journal as PDF
Practical tip: Journals are helpful for accounting. You can produce a journal of all invoices every month and forward it to your accountant.

Locking System

The locking system protects master data from unintended changes.

How it works

  • In the company module (Locks tab) you can lock individual modules
  • A locked module shows its data but allows no changes
  • The lock applies to all open tabs of the module
  • The lock is monitored in real time — when someone places a lock, all other tabs are notified immediately

E-Invoice Spool

If a customer has the option “Create e-invoice” enabled, the first real print of an invoice automatically generates a machine-readable XML file according to EN 16931 and stores it in app/Spool/E-Rechnung/.

A downstream email client can pick up these files from the spool and send them. Reprints of an already finalized invoice do not generate a new XML — it stays unchanged from the original print.

The spool window lists all files with invoice number, customer, date and size. Double-click a row to open the XML in the default editor; “Show in Explorer” jumps directly to the spool folder.

Currently only the UBL 2.1 syntax is generated; the versions UN/CEFACT CII, XRechnung and ZUGFeRD can already be selected on the customer, but are not yet implemented — a print attempt shows a notice and the PDF is still produced normally.

Set up Gmail

Gmail does not allow sending with your regular account password. You need an app password:

  1. Enable 2-factor authentication on your Google account (required for app passwords).
  2. Generate a new app password at https://myaccount.google.com/apppasswords (label e.g. “Order-Management”).
  3. Enter the 16-character password under Company settings → Parameters → Gmail app password together with the matching Gmail address.

The app password is stored in plain text in the database — protect the DB accordingly. If you lose a device, you can revoke the app password at any time using the Google link above.

Company Administration

The functions in this area are admin functions and must be activated beforehand in the “Admin Settings” menu.

Copy company

This function lets you use an existing company (including all related data) as a template to create a new company.

What is copied:

  • Company address and contact details
  • All customers and articles
  • All documents and line items (quotes, orders, delivery notes, invoices, reminders)
  • Fiscal years and document counters
  • Base interest rates

Important to know:

  • The copied company gets a new, own ID
  • Customer numbers and article numbers remain identical to the source
  • Documents get new numbers based on the counters of the new company
  • Global tables (VAT classes, payment terms, reminder terms) are not copied
  • The copy is a complete, independent company

Delete company

Deleting a company can be done in two ways:

Soft delete (default):

  • The company is marked as “deleted”, but the data remains in the database
  • Deleted companies can be restored if needed
  • This is the default function and requires no activation

Hard delete (admin):

  • The company is completely removed from the database together with all related data
  • This action is irreversible
  • Enable “Enable company deletion” in the admin settings
  • On hard delete you can choose which data is deleted (documents, master data, or everything)
Caution: Hard delete is final. Before complete deletion you should create a backup of the database.

Import / Export

The application supports exporting and importing all data.

Export data

Menu File → Export data:

  • All data is written to a JSON file
  • The file is saved in the application directory
  • Use this for backups or for moving to another system

Import data

Menu File → Import data:

  • Select a previously exported JSON file
  • The data is added to the existing database
Caution: Imported data is added — existing data is not automatically deleted. If you want to import data into an empty database, you should back up the database file first and then delete it.

Spell Checker

The application checks spelling in free-text fields and standard texts.

How it works

  • Misspelled words are underlined with a red wavy line
  • The check runs automatically after a 400 ms pause (when you stop typing)
  • Applies to all free text fields and text areas

Abbreviations and technical terms

The application already knows a number of technical terms and abbreviations (e.g. “USt-ID”, “Mahnkondition”, “SEPA”, “IBAN”, “BIC”). These are not marked as errors.

If the spell checker does not work

The check requires Hunspell dictionaries for German. If none are installed the application still works — only without underlining of errors.

Solution: Install Hunspell with German dictionaries (de_DE.aff / de_DE.dic). Alternatively pyenchant works with a system-wide Hunspell.

Settings

Under Settings (menu or sidebar bottom):

Test Mode

Test mode lets you test the application with shifted data without falsifying the real date.

Activate

  1. Open the company module
  2. Activate the checkbox “Enable test mode” (next to “Show deleted companies”)
  3. A button +10 appears in the sidebar below the document date

How it works

  • Every click on +10 advances the document date by 10 days
  • This way you can quickly jump into the “future” and test e.g. reminders or due dates
  • Test mode is stored in the settings (persistent)
  • The document date itself is not persistent — on restart it returns to “today”

Database & Backup

All data is stored in an SQLite database (app/daten/auftragsabwicklung.db).

Automatic schema updates

On application start the database version is checked and automatically brought to the current state. You do not need to do anything manually.

Creating a backup

A backup is easy — just copy the database file:

copy app\daten\auftragsabwicklung.db app\daten\auftragsabwicklung.db.bak

Or use the export function in the menu (Menu File → Export data).

Recommendation

Back up regularly! It is recommended to back up the database regularly — e.g. after every change to important documents. A simple method: copy the database file into a backup directory with date.

Notes & Frequently Asked Questions

Why does the document number only appear on save?

The number is only assigned on save so unsaved documents do not consume a number. If you create a document and then close it, the counter stays unchanged.

What happens when the VAT rate changes?

Every line item stores the VAT rate at the time of its creation. A change of the rate only affects new line items. Old documents stay correct.

Can I restore deleted documents?

Yes. Since all deletions are “soft delete”, the data stays in the database. You can use the “Restore” function to bring the document back.

Why can I not delete a document?

If the document has live successors (e.g. a quote from which an order has been created), deletion is prevented. You must first delete or restore the successors.

Why does the spell checker not appear?

The check requires Hunspell dictionaries. If none are installed the application still works, but without underlining of errors. See Spell Checker.

Page numbering in PDFs

Page numbering is in the format total - current (e.g. 2 - 1, 2 - 2).

Can I edit multiple documents in parallel?

Yes. You can have several tabs open at once and switch between them. Each tab works with the same data, but every change only takes effect when saved.

What is the creation date?

The creation date is locked on the first print of a document (date + time). After that it stays unchangeable and appears in the document dialog as well as in the PDF header (top right). On a test print no creation date is stored.
